# 桃園煉油廠 歷史事件題庫（去識別化）

> 來源：/doc 內約 210 份內部速報與對外新聞稿／聲明稿，期間 2017–2025（民國 106–114）。
> 已去識別化：移除個人手機、員編、通報名單；人名僅保留「姓氏＋職稱」程度。
> 用途：① 新聞稿生成的案例庫 ② 可勾選介面的選項來源 ③「該不該對外發稿」的判斷依據。

## 一、先認清：資料裡有兩種文體，三份官方範本

**兩種文體（用途相反，別混為一談）**

| | 工安速報 | 對外新聞稿／聲明稿 |
|---|---|---|
| 形式 | 固定欄位表單「災害及緊急事件速報表」 | 段落文章 |
| 對象 | 對內＋主管機關 | 媒體／大眾 |
| 時機 | 事件第一時間，逐報更新至結報 | 經篩選與語氣加工後 |
| 內容 | 含設備、時序、傷亡、通報機關、個資 | 不含個資，認責謹慎 |
| 數量 | 2024–2025 為主（PDF） | 2017–2024（docx 為主） |

**三份官方範本（產品應直接沿用，不要自創）**

1. **輿情預警／突發新聞事件通報表**（`0315桃廠輿情預警突發新聞事件通報表.docx`）
   官方的對外回應決策表。欄位：日期、單位、議題、**主要爭點**、**回應基調**、預擬回應內容、**有無媒體／地方意見領袖／民代關切**（含關切重點）、建議處理方式；簽核：擬稿人 → 核稿主管 → 單位發言人。
   → 這份就是「案例卡 schema」＋「該不該回應的判斷欄位」的官方版。

2. **空白新聞稿**（`空白新聞稿.docx`）
   官方對外版型：第一段／第二段 ＋ 固定頁尾（煉製事業部桃園煉油廠、發言人〔副廠長〕、新聞聯絡人〔課長〕、聯絡電話）。
   → 這是生成器的標準輸出格式。

3. **災害及緊急事件速報表**（每份速報 PDF 的共用表頭）
   欄位：報別（未結報／結報・第N報）、通報部門、事件名稱、發生地點／時間、速報時間、類別（災害／預防性通報）、等級（丙級等）、發生原因／訴求、現場狀況、處理情形／擬採對策、人員傷亡（死亡／受傷／失蹤 × 員工／承攬商／其他）、緊急應變中心成立/解除、通報勞檢環保警消情形、**媒體關切或報導情形**、財物損失。
   → 這是生成新聞稿的「事實底稿」輸入格式。

> 注意：`中油近3年新聞分析.docx` 是早期 AI 產生的空泛摘要（模型未實際讀到資料），不可當事實來源。

## 二、事件分類題庫

每類含：定義範圍、代表案例（日期＋一句話）、典型回應基調、是否通常對外發稿。
標註慣例：⚠️＝多為對外新聞稿／聲明稿；🔒＝多為對內速報、通常不對外。

- 2023-08-16 變電站主開關跳電（出新聞稿＋QA＋時間表）
- 2024-12-29 第一動力工場四、五號鍋爐跳車造成工場停爐（多工場改循環操作）
- 2025-01-07 VGO 工場真空塔保溫層疑似滲漏
- 2025-01-11~13 開爐中工場主變電站跳電
- 2025-01-15~20 #5 鍋爐 DCS 系統備用 IO 控制器故障 → 卡片檢修
- 2025-05-01 重油轉化工場觸媒循環不良、暫停進料
- 2025-05-04~19 重油轉化工場膨脹機 GE-7201 振動過高（預防性通報，第1報→結報）
- 2025-05-28 一蒸側塔 D-103 柴油汽提蒸氣管線砂孔漏

回應基調：強調已控制、無外溢風險、持續監控、配合查修。

### B. 漏油／管線洩漏 ⚠️🔒（約 18 起）

- 2023-12-18~19 航空燃油管遭洩漏（1600→次日1000）
- 2025-03-15~16 大園三民路二段地下管線疑破裂漏油（第1報→第3報結報，已成立前進指揮中心、通報環保局與經發局）
- 2025-04-16 R1 預防性通報
- 2025-04-25 本廠管線遭台電施工受損洩漏（第1報疑似→第4報，多報追蹤）

### C. 工安／人員傷亡與健康 🔒（約 12 起）
員工作業受傷、化學品接觸、身體不適送醫、上下班交通事故。多為對內速報。**車禍多屬通勤事故、非廠區工安**，分類時要區分。

- 2025-01-03~04 R1 鍾姓同仁突然身體不適送醫（第1報→結報）
- 2025-02-07 交通事故（第1報→結報）
- 2025-03-12 轉化處理工場員工作業時遭鹼液噴濺（面部，送長庚；第1報→結報，丙級）
- 2025-03-13 西硫工場邱員身體不適送醫（第1報→結報）

### D. 環保／污染爭議 ⚠️（約 9 起）

## 三、把題庫接回產品（重點結論）

1. **事件類型分佈很集中**：設備/製程、漏油/管線、工安人員、環保污染四類佔絕大多數，且是石化廠會重複發生的。題庫應以這四類為主力訓練生成器。

2. **「該不該對外」有現成標籤**：速報的「媒體關切或報導情形」＋通報表的「有無媒體／民代關切」＋事件等級，就是判斷依據。2025 年大量速報（跳電、鍋爐、身體不適、通勤車禍）媒體關切＝無、屬丙級／預防性通報，**多數未對外發稿**——這正是訓練「不要見獵心喜亂發稿」的負樣本。

3. **多版本迭代是常態，且有時間戳**：漏油、共存共榮、感謝部桃等都有 1500/1520/1530 或 v1→v7 的密集修版。這驗證了你的「局部重寫、版本控制」設計是真需求。

4. **演習腳本＝免費的情境題庫**：直接拿 CIP 演習假新聞稿當生成器的測試題與 few-shot 範例，覆蓋外海洩漏、化學物污染、不明爆裂物、假消息等劇本。

5. **三份官方範本是地基**：輸入用「速報表／通報表」欄位，輸出套「空白新聞稿」版型，決策用通報表的關切欄位。產品不必發明格式，沿用中油現行的就最貼合實際、也最有說服力。
