## 踩的坑（教訓）
1. **GitHub PAT 明文貼進終端機指令 → 曝光**。改用：編輯 `.dev.vars` 檔或 `wrangler secret put`（隱藏輸入），**絕不 echo/貼聊天**。已 revoke 重發。
2. **想把 APP_KEY 嵌入公開頁面 → 等於洩漏**（頁面公開時誰都看得到）。正解：同網域 `/api` + 一道 Access，**不需前端密鑰**。
3. **wrangler.toml 加 `routes` 後，workers.dev 預設被關掉** → 差點斷現有 demo。過渡期補 `workers_dev = true` 並存，最後再關。
4. **GitHub Models 免費版有速率限制（429）**：反覆測試會打爆，主路暫時出不了稿。對策：控制測試頻率、demo 前確認額度、或加 Anthropic fallback。
5. **gpt-5 / o3 / o4 推理模型拒收 `max_tokens`**，要 `max_completion_tokens`；`gpt-5-chat` 則可用 `max_tokens`。worker 已自動依模型挑參數。
6. **瀏覽器快取舊頁面**導致看到舊行為（如 (來源:) 標記）。對策：本機用 no-cache server、或硬重整 Cmd+Shift+R。
7. **Pages 自訂網域的 CNAME 沒自動建**（zone Active 但無 DNS 記錄）→ 需手動建 CNAME `response`→`news-response.pages.dev`（Proxied）；DNS 傳播 + Edge SSL 簽發要等十幾分鐘。
8. **去識別化人名也在 init commit 歷史** → 單改檔不夠，squash 全部 commit 成單一乾淨 commit + `gc --prune` 清舊物件。
9. **Cross-machine**：長官名單/校正詞庫存在 `officials.json`/`corrections.json`（已 commit、build 內嵌），故換機器會自動帶出；但 Worker 端點、API key 等不可入庫者見「新機器接手須知」。
