# 階段二：網路新聞採集分析（打造題庫與資料庫的種子）

目標：用過去公開新聞，反推「**這種單位真正會發生什麼事**」，產出三份歸納，餵給第 3、4 階段：
(1) 事件型態清單（→ event_types）、(2) 設備/地點/物質/處置詞彙（→ OPTIONS、corrections）、
(3) 敏感爭點與媒體框架（→ response_tone、typical_disputes、題庫情境）。

## 怎麼搜（能上網時用 WebSearch / WebFetch）

針對「本單位」與「同型態單位」各搜一輪，查詢詞範例：
- 本單位：`"<單位全名>" 事故 OR 外洩 OR 抗議 OR 環評 OR 跳機`、`"<簡稱>" 新聞 中油`
- 同型態：`天然氣接收站 外洩 OR 氣爆 OR 海象 OR 環評 台灣`、`油庫 油氣 異味 居民`
- 主管機關/在地：`<縣市>環保局 <單位> 裁罰 OR 稽查`、`<在地議題,例 大潭藻礁> 中油`
- 時間盡量涵蓋近 5~10 年；每個事件抓 2~3 篇不同來源交叉比對。

不能上網時：請使用者貼新聞標題/連結/內文，照同樣方法歸納。

## 萃取每則新聞成結構（寫進工作筆記，先不入庫）

| 欄位 | 說明 |
|---|---|
| date / title / outlet | 日期、標題、來源（用於溯源，不照抄全文） |
| event_kind | 你歸的事件類型（後續聚合成 event_types） |
| location / equipment / material | 出現的地點/設備/物質詞（→ OPTIONS 候選） |
| dispute | 媒體/居民/民代的爭點與質疑 |
| official_response | 官方當時怎麼回應（基調、用詞） |
| outcome | 後續（裁罰/澄清/改善承諾） |

## 聚合分析（給使用者看的中間產物）

1. **事件型態頻譜**：把 event_kind 聚成 3~10 類，標每類出現頻次與對外敏感度 → 候選 event_types。
2. **詞彙抽取**：地點/設備/物質/處置高頻詞去重 → 候選 OPTIONS 各群組；常被誤寫/誤聽的專有名詞 → corrections。
3. **爭點地圖**：每類事件最常見的 3 個爭點 + 官方慣用回應基調 → response_tone / typical_disputes。
4. **題庫情境**：每類挑 1~2 個代表事件，寫成「情境題」（事件＋該勾哪些要素＋期望稿件重點），供測試與 few-shot。

## 治理紅線
- 新聞含人名（傷亡者/民眾/承辦）一律**去名**再記錄；不要把第三方姓名寫進單位包。
- 萃取的是**結構化事實與情境**，不是照抄新聞全文（避免著作權與不實傳播）。
- 所有 web 來源案例標 `source:"web"`、`verified:false`；具體數字未經單位確認標 `[待確認]`。
- 把這些當「題庫種子」，最終 event_types/few-shot 仍需使用者審過。
